# Saved artifacts and integrity

New run data is saved under the explicit marked project's `runs/` directory.
Physical storage is independent from whether large data is committed to Git.
Input datasets and suites generated by native commands live under `inputs/`.

## Roots and references

A standalone run owns one attempt root. A series owns its inputs, immutable plan,
controller state, attempts, reports and exports. Internal file references contain
exactly `path` and the SHA-256 of actual bytes. Paths are portable relative paths
against the explicitly supplied bundle root, never the containing JSON directory.
Parent segments, absolute paths, backslashes and control characters are invalid.

The project marker UUID and relative `runs/...` bundle path form the portable
project binding. A complete project may move to another absolute path while
retaining that binding. A different project marker does not silently adopt it.

Input materialization first verifies the complete acyclic reference closure.
Original bytes remain under `provenance/original/`. Problem, oracle, history and
configuration files are copied byte for byte. Only declared metadata reference
positions are rewritten under `inputs/`, in dependency order. The immutable
materialization receipt records original/native hashes, each reference mapping
and the semantic projection. Free metadata is not interpreted as a file reference.

## Source and environment

Builds carry `_source_inventory.json` and `_build_provenance.json`. The inventory
contains actual package Python files and packaged schema JSON, under logical
`otqa/...` paths. Checkout and wheel use the same logical namespace. Its digest
is canonical UTF-8 JSON of the entire inventory document, with sorted keys and
no final newline. The two stamps exclude themselves to avoid a hash cycle.

Runtime recomputes the actual included file list, sizes and hashes. Missing,
additional or changed production files invalidate a stamp. Source identity is
the inventory format plus digest. Version, Git commit and dirty flag are immutable
build provenance; saving run data does not change the production source identity.
Python/package versions, capabilities and environment locks are bound separately.

## Durable start and journal

The supervisor publishes a launch intent before spawn. The isolated child writes
its real identity and waits for a private one-shot release channel. The owner
checks the identity and durably binds a matching grant before sending the pulse.
EOF before release exits without numerical imports, workers or a solver call.

Only the CaseProcess writes `events.jsonl` and `progress.json`. Required barriers
are start, selected plan plus dispatch before provider entry, each accepted answer
before successor analysis, and terminal completion. Append alone is not a commit.
The cursor is published only after journal fsync and atomic durable cursor write.
Any required failure poisons that writer and retains its last confirmed cursor.

The cursor binds prefix bytes, hash, sequence, counts, phase and process identity.
Readers may observe a journal larger than the cursor; later bytes do not increase
confirmed answers. Without a valid cursor, confirmed progress is unknown.
Recovery never infers a missing successful start cursor from readable raw bytes.

Counts distinguish declared initial answers, newly dispatched questions, newly
accepted answers, and total accepted answers. Open prompts increase dispatches,
not accepted answers. Uncommitted memory state belongs only to error diagnostics.

Each terminal `result.json` is immutable. Failed and interrupted attempts retain
their raw journal suffixes and prior attempts. A controller cannot relabel a
partial/crashed run as a regular solver return or overwrite a CaseProcess result.

## Numbers and quality

Strict JSON rejects BOMs, duplicate keys, non-finite values and implicit numeric
conversions. Integer fields require actual integers, excluding booleans and `2.0`.
Mathematical values have pointer-indexed canonical `float.hex()` evidence, including
signed zero and mathematical values written as JSON integers. Counts and times
are distinct and do not acquire mathematical hex entries.

Simulation uses stored raw binary64 weights. The independent auditor interprets
those floats exactly with rational arithmetic, checks every answer sign and finds
the complete tied-winner set. Regret is an exact rational string. A confidence
selection can be mathematically consistent yet incorrect; this is visible quality
data, separate from an integrity or oracle-consistency failure.

## Reports and exports

Native reports are under `reports/<UUID>/`; exports are under `exports/`. An audit
binds one immutable state snapshot and, for running attempts, verified immutable
prefix snapshots. A summary and export reuse that exact basis. Later journal
growth is allowed; prefix modification or shortening is rejected.

Summaries recompute from verified raw attempts. They retain every planned row,
all result references and separate solution, correct-solution, completed-call,
failed-call and controller-attempt distributions. Empty samples have `n=0` and
null statistics. CSV exports also retain audit/plan/state hashes in columns and
have a sibling receipt. Moving one report is not equivalent to archiving its data.

Native qualification raw reports have method-specific required observations and
pass rules. Existing files or a self-declared top-level passed flag do not suffice;
unknown, incomplete, incorrectly bound or failed evidence is rejected. Analytical
and format controls remain distinct from actual installed/process checks.
